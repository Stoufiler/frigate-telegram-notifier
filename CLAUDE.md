# Frigate Telegram Bot

Go bot that bridges Frigate NVR events to Telegram notifications via MQTT.

## Build & Run

```bash
make build          # build binary (version injected from git tag)
make lint           # golangci-lint (gofmt, gosec, misspell, staticcheck, …)
make fmt            # auto-format code
make test           # go test -race
make changelog      # generate CHANGELOG.md via git-cliff
make docker         # docker build with version
make clean          # remove binary
```

## Project Layout

```
bot/
  main.go       — entrypoint, MQTT wiring, version flag
  config.go     — env-based configuration (LoadConfig)
  event.go      — MQTT dispatch, review handlers, captions
  frigate.go    — Frigate HTTP client (snapshot, preview, event description)
  notifier.go   — Telegram client (text, photo, animation)
  i18n.go       — localization setup, tr() helper
  locales/      — en.json, fr.json translation files
```

## Conventions

- **Go 1.27**, module at `bot/go.mod`
- **Conventional commits** — `feat:`, `fix:`, `refactor:`, `ci:`, `docs:`, `chore:`
- Changelog generated by **git-cliff** from commit history
- Version injected at build time via `-ldflags -X main.version=...`
- Linting: **golangci-lint v2** with config at `.golangci.yml` (run from `bot/`)
- Translations: all user-facing strings go through `tr()` / `translateLabel()` — never hardcode text
- No comments unless the WHY is non-obvious
- Env vars are the only configuration mechanism — no config files at runtime

## Key Design Decisions

- The bot listens to `frigate/reviews` (not `frigate/events`) for consolidated review items
- Availability monitoring via `frigate/available` topic (derived from reviews topic prefix)
- GenAI descriptions are opt-in (`FRIGATE_GENAI=true`) — fetched from `/api/events/<id>` on event end
- Frigate auth uses cookie-jar login with automatic re-auth on 401
- Sub-labels, audio, and severity are parsed from the review MQTT payload
- Snapshot API uses `bounding_box=1` parameter (Frigate 0.18+ only, `bbox` dropped)

## Releasing

1. Tag: `git tag v0.X.Y && git push --tags`
2. CI builds binaries, Docker image, generates changelog, creates GitHub Release
